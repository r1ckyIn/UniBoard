<task type="auto">
  <name>Task 2: Preserve form mode across language switches</name>
  <files>frontend/components/auth/AuthPage.tsx, frontend/components/auth/LanguageSwitcher.tsx</files>
  <action>
    Fix the language switcher resetting form state from register back to login.

    Root cause: `AuthPage.tsx` stores form mode in `useState("login")` which resets on remount. `LanguageSwitcher.tsx` calls `router.replace(pathname, { locale })` which triggers a full component remount via next-intl routing, losing the React state.

    Solution: Persist form mode in URL search params (`?mode=register`).

    1. In `frontend/components/auth/AuthPage.tsx`:
       - Import `useSearchParams` from `next/navigation`
       - Import `useRouter` and `usePathname` from `next/navigation` (keep existing useRouter import)
       - Read initial mode from `searchParams.get("mode")` — if value is "register", start in register mode; otherwise default to "login"
       - Replace `useState<"login" | "register">("login")` with a computed initial value from searchParams
       - When `setMode` is called (via `onSwitchMode`), also update the URL search params using `router.replace` with the new mode param (use `window.history.replaceState` or `router.replace(pathname + "?" + newParams)` to avoid full navigation). Use `useCallback` to create a `handleSwitchMode` function that both updates local state AND updates the URL.
       - Keep `useState` for the actual mode (for responsive reactivity), just initialize from URL and sync on change.
       - IMPORTANT: Use `useSearchParams` from `next/navigation` (not from next-intl navigation). The `usePathname` and `useRouter` already imported from `next/navigation` are fine.

    2. In `frontend/components/auth/LanguageSwitcher.tsx`:
       - Import `useSearchParams` from `next/navigation`
       - In `toggleLocale`, read current search params and pass them through when switching locale
       - The next-intl `router.replace(pathname, { locale })` loses search params. Instead, construct the full URL with search params preserved: get the current `searchParams.toString()`, and use the next-intl router with the pathname that includes the query string, OR use window.location-based approach.
       - Simplest correct approach: use `useSearchParams()` from next/navigation, then in toggleLocale: `const params = searchParams.toString(); const fullPath = params ? \`\${pathname}?\${params}\` : pathname; router.replace(fullPath, { locale: nextLocale });`
       - This preserves `?mode=register` when switching language.
  </action>
