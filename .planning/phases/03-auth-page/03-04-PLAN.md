  <name>Task 1: RoughCard smooth border transitions and disableHover prop</name>
  <files>frontend/components/design-system/RoughCard.tsx, frontend/components/auth/AuthFormCard.tsx</files>
  <action>
    Fix two issues in RoughCard.tsx:

    **Issue 1: Border snap/jitter on resize**

    Root cause: (A) Each `drawBorder()` call generates new random rough.js paths (no fixed seed), causing visual jitter. (B) ResizeObserver + single rAF fires discretely, not tracking continuous framer-motion layout animations.

    Fix A — Add fixed seed to rough.js options:
    - In `drawBorder()`, add `seed: 42` to the `rc.rectangle()` options object (line 36-42). This makes rough.js produce the exact same hand-drawn wobble pattern every time, eliminating visual jitter when the border redraws at a new size. The shape will scale smoothly because only width/height change while the randomness pattern stays constant.

    Fix B — Replace single-rAF ResizeObserver with continuous rAF loop during transitions:
    - Add a ref `isTransitioning` (useRef<boolean>(false)) and `rafLoopId` (useRef<number | null>(null))
    - Create a `startTransitionLoop()` function that runs `drawBorder()` on every animation frame using `requestAnimationFrame` recursively, and a `stopTransitionLoop()` that cancels it
    - Expose these via a new prop `onTransitionStart?: () => void` and `onTransitionEnd?: () => void` — OR simpler approach: use a `transitionDuration` prop (number in ms, default 0) that triggers a continuous rAF loop for that duration after any ResizeObserver event.
    - SIMPLEST approach (preferred): Instead of a prop-based API, just change the ResizeObserver callback to run a short burst of rAF redraws. When ResizeObserver fires, start a rAF loop that runs drawBorder() for ~400ms (matching the spring animation duration), then stops. Track with a timestamp: `const start = performance.now(); const loop = () => { drawBorder(); if (performance.now() - start < 400) rafId = requestAnimationFrame(loop); }; loop();`
    - Keep the ResizeObserver — it triggers the rAF burst. The burst ensures the border follows the height change frame-by-frame during the spring animation.

    **Issue 2: Unwanted hover float on auth form card**

    Fix:
    - Add `disableHover?: boolean` prop to `RoughCardProps` interface (default `false`)
    - Conditionally apply hover classes: only include `"hover:shadow-card-hover hover:-translate-y-px"` when `disableHover` is falsy
    - This keeps hover effects on all existing RoughCard usages (dashboard, sidebar, etc.) while allowing the auth form card to opt out

    **AuthFormCard update:**
    - In `frontend/components/auth/AuthFormCard.tsx`, add `disableHover` to the RoughCard usage: `<RoughCard padding="px-8 py-9" className="overflow-hidden" disableHover>`
    - Keep the `layout` prop on the outer motion.div — it's needed for smooth height morphing during login/register switch. The entrance jank will be fixed in Task 2 by changing the entrance animation approach.
