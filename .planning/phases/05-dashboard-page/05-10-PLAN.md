**B. Fix right sidebar sticky positioning:**

The root cause: `<main>` has no `overflow-y-auto` and no height constraint, so the browser's viewport is the scroll container, but the `sticky` element needs its nearest scrollable ancestor to have constrained height.

**In `frontend/components/layout/AppShell.tsx`:**

Change the `<main>` element from:
```tsx
<main className="flex-1 py-7 px-8">
```
to:
```tsx
<main className="flex-1 py-7 px-8 overflow-y-auto" style={{ maxHeight: "calc(100vh - var(--spacing-header-h))" }}>
```

This makes `<main>` the scroll container with a constrained height (viewport minus header), which allows `sticky` positioning inside it to work correctly.

**In `frontend/components/layout/RightPanel.tsx`:**

1. Remove `overflow-y-auto` and `overflow-x-hidden` from the panel div (these conflict with sticky — the panel itself should not scroll independently; the main scrolls).
2. Remove `self-start` (redundant with sticky).
3. Keep `sticky` and `top-[...]` and `max-h-[...]`.
4. Add internal overflow handling: wrap the `#right-panel-slot` div in a scrollable container so if right panel content exceeds viewport it can scroll internally.

Updated className:
```tsx
className={cn(
  "w-[var(--spacing-right-panel-w)] flex-shrink-0",
  "hidden xl:flex xl:flex-col items-start",
  "gap-[18px] sticky top-0",
  "max-h-[calc(100vh-var(--spacing-header-h)-56px)]",
  "overflow-y-auto overflow-x-hidden",
  // scrollbar styles unchanged...
)}
```

Key change: `top-[calc(var(--spacing-header-h)+28px)]` changes to `top-0` because inside the `<main>` scroll container, the top edge is already below the header. The 28px padding comes from main's py-7.

Also update the parallax scroll listener in HeroSection.tsx: change `window.scrollY` to check for the main scroll container instead. Since HeroSection is inside main, use `heroRef.current?.closest('main')?.scrollTop` for the scroll offset:
