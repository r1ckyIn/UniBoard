## Architecture Patterns

### Fixture Data Flow
```
fixture .ts file → Route Handler mock (app/api/[locale]/...) → TanStack Query hook → component
```
Updating fixture files automatically propagates to all consuming components via the Route Handler mock layer. No Route Handler changes needed unless the data shape changes.

### Cross-Page Course Code Consistency
```
course-colors.ts  →  getCourseColor(code)  →  ALL components displaying course colors
courses.ts        →  Route Handler          →  useCourses() hook → Sidebar, Legend, Page lists
deadlines.ts      →  Route Handler          →  useDeadlines() hook → Timeline, Calendar, Timetable overlay
digest.ts         →  Route Handler          →  useDigest() hook → Digest page
discussions.ts    →  Route Handler          →  Course Detail Ed posts panel
materials.ts      →  Route Handler          →  Course Detail materials browser
```

**Key insight:** `course-colors.ts` is the single source of truth for visual identity. Every component calls `getCourseColor(courseCode)` and falls back to DEFAULT_COLOR. Adding new course codes here ensures immediate visual consistency.

## Common Pitfalls

### Pitfall 1: Course Code Mismatch Across Files
**What goes wrong:** Updating courses.ts but forgetting to update digest.ts or discussions.ts leaves orphan course codes that don't match any color or display name.
**How to avoid:** Use a checklist approach -- update ALL 8 files in a single plan. Grep for old course codes (INFO2222, MATH1005) after completion to verify zero remaining references.
**Warning signs:** Components showing grey default color instead of assigned course color.

### Pitfall 2: EDGU1003 Has No Ed Course
**What goes wrong:** Creating Ed discussion fixtures or Ed lesson materials for EDGU1003 when it has no Ed course ID.
**How to avoid:** Set `ed_course_id: null` for EDGU1003 in courses.ts. Remove or empty the discussions entry for EDGU1003. Materials should only have Canvas source entries.

### Pitfall 3: Deadline Date Format Consistency
**What goes wrong:** Using inconsistent timezone formats. Some dates in Obsidian are AEST, some are AEDT. The timezone changes on April 5, 2026.
**How to avoid:** All fixture dates should use ISO 8601 with explicit timezone. For dates before April 5, use +11:00 (AEDT). For dates after, use +10:00 (AEST). Or simpler: use "Z" (UTC) and convert consistently.
**Warning signs:** Deadlines showing at wrong times or on wrong days.

### Pitfall 4: Timetable Deadline Week Filtering Logic
**What goes wrong:** Filtering by teaching week number instead of by actual date range. Teaching weeks have gaps (break week), so a simple week number filter won't work.
**How to avoid:** Use the current week's `monday_date` to compute Mon 00:00 - Sun 23:59 date range, then filter deadlines whose `due_date` falls within that interval.

### Pitfall 5: Existing Test Assertions on Fixture Data
**What goes wrong:** Tests that assert specific fixture values (course names, deadline counts, etc.) will break when fixture data changes.
**How to avoid:** Run `pnpm test` after fixture replacement to identify broken assertions. Update test expectations to match new data.

### Pitfall 6: Assessment Weight Sum Validation
**What goes wrong:** Assessment weights for a course don't sum to 1.0, causing WAM calculations to produce incorrect results on the Predict page.
**How to avoid:** Verify that assessment_weights for each course in courseDetails sum to exactly 1.0 (within floating point tolerance). The real Obsidian data has explicit percentages -- convert carefully.

### Timetable Week Filtering Pattern
```typescript
// Filter deadlines to current viewed week's Mon-Sun range
const weekDeadlines = useMemo(() => {
  if (mode === "all") return deadlineItems;
  const monday = new Date(currentWeek.monday_date + "T00:00:00");
  const sunday = addDays(monday, 6);
  sunday.setHours(23, 59, 59, 999);
  return deadlineItems.filter((dl) => {
    const dueDate = new Date(/* reconstruct from dl fields */);
    return dueDate >= monday && dueDate <= sunday;
  });
}, [deadlineItems, mode, currentWeek.monday_date]);
```

### MiniCalendar Deadline Days Computation
```typescript
// Compute deadlineDays for MiniCalendar from real deadline data
const deadlineDays = useMemo(() => {
  const dayMap = new Map<string, number>();
  for (const dl of allDeadlines) {
    const dateKey = format(new Date(dl.due_date), "yyyy-MM-dd");
    const current = dayMap.get(dateKey) ?? 0;
    dayMap.set(dateKey, current + (dl.weight ?? 0));
  }
  return Array.from(dayMap.entries()).map(([date, totalWeight]) => ({
    date,
    totalWeight,
  }));
}, [allDeadlines]);
```
