  <files>frontend/app/api/v1/users/me/route.ts, frontend/lib/fixtures/gpa.ts</files>
  <action>
    The root cause: PATCH /users/me merges body with `mockUser` into a new object but never mutates the source. The next GET returns the original immutable `mockUser`. Also, predict page reads `target_wam` from a separate GPA fixture, not from the user query.

    **Fix 1: Make mock API stateful** (frontend/app/api/v1/users/me/route.ts):
    - Import `mockUser` from fixtures as before
    - Add a module-level mutable variable: `let currentUser = { ...mockUser };`
    - Change GET handler to return `currentUser` instead of `mockUser`
    - Change PATCH handler to mutate `currentUser`: `currentUser = { ...currentUser, ...body };` and return `currentUser`
    - This ensures PATCH changes persist for subsequent GET calls within the same dev server session

    **Fix 2: Sync GPA fixture target_wam with user fixture** (frontend/lib/fixtures/gpa.ts):
    - The `gpaReport` fixture has `target_wam: 85.0` and the `mockUser` has `gpa_target: 85.0` — these are consistent at rest.
    - The real problem is that changing `gpa_target` via settings PATCH doesn't update the GPA report endpoint. This is acceptable for a mock layer (the backend will handle this properly). But to prevent the "reset" behavior, we need the predict page to read the target from the user query as the source of truth.
    - In `frontend/lib/fixtures/gpa.ts`: export a helper function `getGpaReport(targetWam?: number): GpaReport` that returns the gpaReport with an overridden `target_wam` if provided. Then update the GPA report route handler to read from the current user state.
    - Actually, the simpler and more correct approach: update the GPA report mock route handler (`frontend/app/api/v1/gpa/report/route.ts`) to import `currentUser` and use `currentUser.gpa_target` as the `target_wam`. This keeps everything in sync.

    Wait — module-level state in Next.js Route Handlers may not persist reliably across hot reloads. A better pattern for mock persistence: use a shared module.

    **Revised approach:**
    - Create or update the shared state: In `frontend/app/api/v1/users/me/route.ts`, export the `currentUser` let variable so other route handlers can import it.
    - Actually, Next.js Route Handlers in the same process share module state. So:
      1. In `route.ts`, declare `let currentUser = { ...mockUser }` and export it as a named export.
      2. In the GPA report route handler, import `currentUser` from the users/me route and use `currentUser.gpa_target ?? gpaReport.target_wam` as the `target_wam` in the response.

    **However**, circular imports could be problematic and exporting mutable state from route handlers is fragile. The cleanest solution:

    **Final approach — shared mock state module:**
    - Create `frontend/lib/fixtures/mock-state.ts` with:
      ```typescript
      import { mockUser } from "./users";
      import type { components } from "@/lib/api/types.gen";
      type User = components["schemas"]["User"];
      // Mutable mock state that persists across route handler calls
      export let currentUser: User = { ...mockUser };
      export function updateCurrentUser(updates: Partial<User>): User {
        currentUser = { ...currentUser, ...updates };
        return currentUser;
      }
      export function resetMockState(): void {
        currentUser = { ...mockUser };
      }
      ```
    - Update `frontend/app/api/v1/users/me/route.ts`:
      - Import `currentUser`, `updateCurrentUser` from `@/lib/fixtures/mock-state`
      - GET returns `currentUser`
      - PATCH calls `updateCurrentUser(body)` and returns the result
    - Update `frontend/app/api/v1/gpa/report/route.ts`:
      - Import `currentUser` from `@/lib/fixtures/mock-state`
      - In the GET handler, override `gpaReport.target_wam` with `currentUser.gpa_target` before returning
      - This ensures predict page (which reads from /gpa/report) gets the updated target

    Do NOT modify the gpa.ts fixture file itself — it remains the static seed data. The mock-state module provides the runtime mutable layer.
