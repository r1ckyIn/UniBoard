    **railway.toml** -- Create at project root with these exact contents:

    ```toml
    [build]
    builder = "DOCKERFILE"
    dockerfilePath = "Dockerfile.production"

    [deploy]
    healthcheckPath = "/health"
    healthcheckTimeout = 120
    restartPolicyType = "ON_FAILURE"
    restartPolicyMaxRetries = 3
    ```

    The `builder = "DOCKERFILE"` tells Railway to use our existing multi-stage Dockerfile.production (tini, non-root user, no --reload). The `healthcheckPath = "/health"` uses the existing health endpoint from Phase 22/23 that returns 200 or 503. Railway auto-injects the `PORT` env var which is already handled by `${PORT:-8000}` in Dockerfile.production CMD.

    **frontend/.env.example** -- Update to include all production-relevant variables. Replace entire file content:

    ```
    # Supabase Auth (get values from Supabase Dashboard -> Settings -> API)
    NEXT_PUBLIC_SUPABASE_URL=http://localhost:54321
    NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-anon-key-from-supabase-status

    # Backend API URL (Railway production URL or local dev)
    NEXT_PUBLIC_API_URL=

    # Sentry Error Tracking (get DSN from Sentry Dashboard -> Settings -> Client Keys)
    NEXT_PUBLIC_SENTRY_DSN=

    # Sentry Build-Time (for source map upload -- set in Vercel env vars)
    # SENTRY_AUTH_TOKEN=
    # SENTRY_ORG=
    # SENTRY_PROJECT=
    ```

    The SENTRY_* build-time vars are commented out because they are only needed in Vercel's env vars, not in local .env.

    | `VOYAGE_API_KEY` | Yes (RAG) | Voyage AI Dashboard -> API Keys | `pa-...` |
    | `SENTRY_DSN` | Optional | Sentry Dashboard -> Settings -> Client Keys (DSN) | `https://xxx@o123.ingest.sentry.io/456` |
    | `CORS_ORIGINS` | Yes | Your Vercel production URL | `https://uniboard.vercel.app` |
    | `DEBUG` | Yes | Always `false` in production | `false` |
    | `PORT` | Auto | Injected by Railway automatically | (do not set) |

    3. Note: `model_post_init` in `src/config.py` validates that JWT secret, encryption key, and database URL are not using unsafe defaults when `DEBUG=false`

    **## Vercel (Next.js Frontend)** subsection with:
    1. Setup steps: Create Vercel project -> Link GitHub repo -> Set Framework Preset to "Next.js" -> Set Root Directory to `frontend`
    2. **Environment Variables** table:

    | Variable | Required | Source |
    |----------|----------|--------|
    | `NEXT_PUBLIC_SUPABASE_URL` | Yes | Same as Railway's SUPABASE_URL |

    | `NEXT_PUBLIC_API_URL` | Yes | Railway production URL (e.g., `https://uniboard-backend.up.railway.app`) |
    | `NEXT_PUBLIC_SENTRY_DSN` | Optional | Sentry Dashboard -> Settings -> Client Keys (DSN) -- separate project from backend |
    | `SENTRY_AUTH_TOKEN` | Optional | Sentry Dashboard -> Settings -> Auth Tokens |
    | `SENTRY_ORG` | Optional | Sentry organization slug |
    | `SENTRY_PROJECT` | Optional | Sentry project slug |

    4. Note about mock data: 17 of 29 frontend API route handlers currently serve mock data. In production, these Route Handlers need to be converted to proxy the Python API. This is a known limitation documented in the architecture.

    **## Health Check** -- The `/health` endpoint returns 200 when healthy and 503 when a dependency is degraded. Railway monitors this endpoint per `railway.toml` configuration.
