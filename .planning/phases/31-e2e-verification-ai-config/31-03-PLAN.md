## Tasks

<task id="31-03-01" title="Fix AuthGuard reactive redirect race condition">

<files>
- frontend/components/auth/AuthGuard.tsx (modify)
- frontend/components/auth/LoginForm.tsx (modify)
- frontend/lib/auth/restore-token-status.ts (read)
- frontend/lib/auth/store.ts (read)
</files>

<action>
**Root cause:** AuthGuard Effect 3 (line 52-57) watches `isAuthenticated` reactively. When login triggers `onAuthStateChange → setAuth(isAuthenticated: true)`, the effect fires immediately with stale `tokenConfigured=false` and redirects to /setup — before LoginForm's async `restoreTokenConfiguredIfNeeded()` can complete.

**Fix AuthGuard.tsx — remove reactive redirect, keep only session-check redirect:**

Replace the current Effect 3 (lines 52-57):
```javascript
useEffect(() => {
  if (!hydrated || !sessionChecked) return;
  if (isAuthenticated) {
    router.replace(tokenConfigured ? `/${locale}` : `/${locale}/setup`);
  }
}, [hydrated, sessionChecked, isAuthenticated, tokenConfigured, locale, router]);
```

With a redirect INSIDE Effect 2's `checkSession` (after `restoreTokenConfiguredIfNeeded` completes):
```javascript
useEffect(() => {
  const checkSession = async () => {
    const supabase = createClient();
    const { data: { session } } = await supabase.auth.getSession();

    if (session) {
      useAuthStore.getState().setAuth(
        { access: session.access_token, refresh: session.refresh_token },
        {
          id: session.user.id,
          email: session.user.email ?? "",
          displayName: session.user.user_metadata?.display_name ?? "",
        },
      );

      await restoreTokenConfiguredIfNeeded();
      const configured = useAuthStore.getState().tokenConfigured;
      router.replace(configured ? `/${locale}` : `/${locale}/setup`);
      return; // Already redirecting, don't set sessionChecked
    }

    setSessionChecked(true);
  };
  checkSession();
}, [locale, router]);
```

Remove the entire Effect 3 block. AuthGuard now only redirects on mount when an existing session is found — it does NOT reactively respond to `isAuthenticated` changes during login. LoginForm handles its own navigation.

Remove `tokenConfigured` from the component's Zustand subscription:
- Keep `const { isAuthenticated } = useAuthStore();` for the render gate `if (isAuthenticated) return null;`
- Remove `tokenConfigured` from the destructure since it's no longer needed in effects

**Fix LoginForm.tsx — use router.replace instead of router.push:**

Line 40: Change `router.push(configured ? ...)` to `router.replace(configured ? ...)`.
This prevents /auth from remaining in the history stack after login.
</action>

<task id="31-03-02" title="Fix logout history stack leak & use useLogout hook">

<files>
- frontend/components/layout/Header.tsx (modify, lines 145-160)
- frontend/hooks/use-auth.ts (read, useLogout hook)
- frontend/components/setup/SuccessStep.tsx (modify, lines 60-64)
</files>

<action>
**Root cause:** Header.tsx:157 uses `router.push('/auth')` for logout. This adds /auth to the history stack ON TOP of the pre-logout page. After AuthGuard replaces /auth, the pre-logout page is directly below in the stack, so browser back button shows it.

**Fix Header.tsx — use router.replace + useLogout hook:**

The Header currently has inline logout logic (lines 152-158):
```javascript
onLogout={() => {
  setAvatarOpen(false);
  const supabase = createClient();
  supabase.auth.signOut().then(() => {
    router.push(`/${locale}/auth`);
  });
}}
```

Replace with:
1. Import and use `useLogout` from `@/hooks/use-auth` — this also calls `queryClient.clear()` to prevent stale data
2. Use `router.replace` instead of `router.push`:
```javascript
onLogout={() => {
  setAvatarOpen(false);
  logoutMutation.mutate(undefined, {
    onSuccess: () => {
      router.replace(`/${locale}/auth`);
    },
  });
}}
```

Add to the component body (near other hooks, around line 20-30):
```javascript
const logoutMutation = useLogout();
```

Add import: `import { useLogout } from "@/hooks/use-auth";`

Remove the now-unused `createClient` import if no other code in Header.tsx uses it.

**Fix SuccessStep.tsx — use router.replace for dashboard navigation:**

Line 63: Change `router.push(`/${locale}`)` to `router.replace(`/${locale}`)`.
User should not be able to navigate back to /setup after completing it.
</action>
