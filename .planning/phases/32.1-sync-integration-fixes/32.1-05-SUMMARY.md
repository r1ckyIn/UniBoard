## Fallback Algorithm

```
For each Ed course ec:
    code, semester = extract_course_code(ec.name), extract_semester(ec.name)
    if code and semester:
        ed_index[(code, semester)] = ec           # primary index
    elif code and not semester:
        ed_code_only.setdefault(code, []).append(ec)   # fallback index

For each Canvas course cc where (code, semester) extractable:
    ed_match = ed_index.get((code, semester))     # primary attempt
    if ed_match is None:
        candidates = ed_code_only.get(code, [])
        if len(candidates) == 1:
            ed_match = candidates[0]              # FALLBACK FIRES
            logger.info("course_linking_ambiguous_semester_fallback", ...)
        elif len(candidates) > 1:
            logger.info("course_linking_ambiguous_semester_fallback_skipped", ...)
        # else: 0 candidates -> leave ed_match None, unlinked result
    # ed_match either a primary hit, a single-fallback hit, or still None
    build LinkedCourse(...) with ed_course_id=str(ed_match.get("id", "")) if ed_match else None
```

## Fixture `real_data_user`

```python
@pytest_asyncio.fixture(loop_scope="session")
async def real_data_user(
    test_engine: AsyncEngine,
) -> AsyncGenerator[Profile, None]:
```

**Env-var dependencies** (all required for the fixture to yield):

- `SYNC_REAL_DATA_CANVAS_TOKEN` -- Canvas API token (sandbox)
- `SYNC_REAL_DATA_ED_TOKEN` -- Ed Discussion API token (sandbox)
- `SYNC_REAL_DATA_USER_EMAIL` -- email string for Profile.display_name

**Lifecycle:**

1. Opens a dedicated session on `test_engine`'s factory (separate from test's `session` fixture).
2. Inserts Profile with encrypted Canvas+Ed tokens; commits so the sync pipeline's own `_get_sync_session_factory()` can see the row.
3. Refreshes + yields the Profile object.
4. Finalizer: opens a second session, executes `DELETE FROM profiles WHERE id = user_id`, commits. Profile.courses and all other relationships have `cascade="all, delete-orphan"`, so dependent rows clean up automatically.

**NOTE in fixture docstring:** for real-data runs, the developer must align `DATABASE_URL` (used by `get_settings().database_url` inside the sync pipeline) with `TEST_DATABASE_URL` (hardcoded in top-level conftest.py). Otherwise sync writes land in a different database than the one the test assertions query.
