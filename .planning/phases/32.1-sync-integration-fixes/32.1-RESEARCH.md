### Pattern 1: Two-Step Unit Outline URL Discovery (TRD §2.2)

**What:** Canvas exposes Unit Outline URLs via LTI External Tool configuration. Two calls needed:
1. `GET /courses/{id}/tabs` → find tab with `label` starting with `"Unit Outline"`, extract `tool_id` from `tab.id` (format `"context_external_tool_{tool_id}"`)
2. `GET /courses/{id}/external_tools/{tool_id}` → read `custom_fields.url`

**When to use:** During course discovery sync (`sync_all_courses`), after upserting each course.

**Example:**
```python
# Source: TRD §2.2 canvas_get_unit_outline_url + src/adapters/canvas.py (get_tabs, get_external_tool already exist)
async def _resolve_unit_outline_url(
    adapter: CanvasAdapter, canvas_course_id: str
) -> str | None:
    tabs = await adapter.get_tabs(canvas_course_id)
    outline_tab = next(
        (t for t in tabs if str(t.get("label", "")).startswith("Unit Outline")),
        None,
    )
    if not outline_tab:
        return None
    tab_id = str(outline_tab.get("id", ""))
    # Format: "context_external_tool_12345"
    if not tab_id.startswith("context_external_tool_"):
        return None
    tool_id = tab_id.removeprefix("context_external_tool_")
    tool = await adapter.get_external_tool(canvas_course_id, tool_id)
    custom_fields = tool.get("custom_fields", {})
    if isinstance(custom_fields, dict):
        url = custom_fields.get("url")
        if isinstance(url, str) and url.startswith("https://sydney.edu.au/units/"):
            return url
    return None
```

### Pattern 3: Course Code Extraction for Ed Course Matching

**What:** Ed Discussion course names follow patterns like `"COMP2017 Semester 1 2026"` or `"COMP2017_Sem1_2026"` or even just `"COMP2017 Systems Programming"` (no semester at all). The current `link_courses` requires BOTH code + semester; when Ed omits semester, the course falls into `"canvas-only, unlinked"` branch.

**When to use:** In `course_linking.py`, allow course-code-only matching as a fallback when Canvas has a unique course for that code in the target semester.

**Anti-patterns to avoid:**
- **Fuzzy-matching course names:** USYD course codes are unique per semester — don't use Levenshtein on names when the code regex already gives a deterministic key.
- **Silent `TokenInvalidError` swallow:** `_sync_user_grades` catches `TokenInvalidError` and sets `degraded`, but returns count=0 which is indistinguishable from "success but no new grades." `sync_all_grades` already has a guard on this (`records_updated > 0`) — preserve this pattern.

## Common Pitfalls

### Pitfall 1: `Course.unit_outline_url` is never populated (SYNC-FIX-01 — root cause)
**What goes wrong:** `sync_all_outlines` runs on schedule but finds zero courses to process because the WHERE clause is `Course.unit_outline_url.isnot(None)` and that column is never assigned anywhere in the codebase.
**Why it happens:** The URL-discovery step (TRD §2.2 two-call flow: `get_tabs` → find "Unit Outline" tab → `get_external_tool` → read `custom_fields.url`) was designed but never wired into `sync_all_courses._upsert_courses`. The `CanvasAdapter` methods exist (`get_tabs`, `get_external_tool`) but have no caller.
**How to avoid:** In `src/sync/courses.py::_upsert_courses`, after creating/updating a course with a `canvas_course_id`, call a new helper `_resolve_unit_outline_url(adapter, canvas_course_id)` and persist the result. Gate the call behind a `if not existing.unit_outline_url:` check to avoid unnecessary API hits every sync.
**Warning signs:** `SELECT COUNT(*) FROM courses WHERE unit_outline_url IS NOT NULL` returns 0. `sync_outlines_skip` log with `reason="no courses with outline URLs"`.

### Pitfall 2: USYD CSS-class selectors may be stale (SYNC-FIX-01 — secondary cause)
**What goes wrong:** `UnitOutlineParser._parse_row` first tries CSS classes (`.assessment-type`, `.assessment-weight`, etc.), then falls back to positional cell parsing. If USYD has changed class names (TRD says "verified in 2025" but we're now in 2026-04), the CSS path returns empty tags; positional fallback kicks in, but it only searches cells for a `%` pattern — `.assessment-due`, `.assessment-length`, `.assessment-description`, `.assessment-use-of-ai` have no positional fallback, so those fields come back empty.
**Why it happens:** Website DOM drift between verification date and now. The parser was built defensively for name + weight but not for the auxiliary fields.
**How to avoid:** Before writing fixes, run a one-off script: fetch `https://sydney.edu.au/units/COMP2017/2026-S1C-ND-CC` and `COMP3221/2026-S1C-ND-CC` (from TRD §11.1), save HTML to `tests/fixtures/usyd/`, then run the parser against them and diff the result against expected weights. If CSS selectors miss, add positional fallbacks for all 6 fields using column-header text matching (find `<th>` containing "Weight" / "Due" / "Length" and use its column index).
**Warning signs:** `UnitOutline.assessments` rows have `weight=0.0` and `due_date=None` and non-empty `name`.

### Pitfall 3: Canvas Assignment list doesn't include `submission.score` by default (SYNC-FIX-02 — root cause)
**What goes wrong:** `src/sync/grades.py::_sync_user_grades` calls `adapter.get_assignments(course_id)` and reads `assignment["submission"]["score"]`. But `GET /courses/:id/assignments` without `include[]=submission` omits the `submission` field entirely, so `submission.get("score")` is always None. Result: every `Grade` row is upserted with `score=None`, and the routes compute `current_mark=None` because `[g for g in grades if g.score is not None]` is empty.
**Why it happens:** The `CanvasAdapter.get_assignments` method doesn't pass `include[]=submission`; TRD §2.2 `canvas_get_grades` explicitly documents the need for `include[]`.
**How to avoid:** Two options:
  (a) Change `CanvasAdapter.get_assignments` to accept an `include` kwarg, pass `["submission"]` from the grades sync. Breaks nothing because deadlines sync also calls `get_assignments` and benefits from richer data.
  (b) Use the Enrollments endpoint for per-course summary grades (`current_score` / `final_score`) and store them directly on `Course` (requires schema change — `current_mark` / `grade_letter` don't exist on Course model; they're computed at read-time in `src/web/routes/courses.py::list_courses`).
**Recommended:** Option (a) — minimal schema impact, matches existing data model.
**Warning signs:** `SELECT COUNT(*) FROM grades WHERE score IS NOT NULL` returns 0 after sync ran successfully.

### Pitfall 4: Ed course name semester extraction fails (SYNC-FIX-03 — root cause)
**What goes wrong:** `link_courses` indexes Ed courses by `(code, semester)` composite key. If Ed course name is `"COMP2017 Systems Programming"` (no semester), `extract_semester` returns `None`, the course never enters `ed_index`, and no Canvas course can match against it.
**Why it happens:** Ed course naming is not standardized — some instructors include semester (`"COMP3221 2026 Semester 1"`), others don't. The current regex patterns assume semester is always present.
**How to avoid:** Two-tier matching:
  1. First pass: `(code, semester)` exact match (current logic)
  2. Second pass for unmatched Canvas courses: if the `code` appears in exactly one Ed course and that Ed course had no extractable semester, link them (single-candidate fallback)
  Keep a log warning `course_linking_ambiguous_semester` when the fallback fires.
**Warning signs:** `SELECT code FROM courses WHERE ed_course_id IS NULL AND canvas_course_id IS NOT NULL` shows courses the user knows are on Ed.

### Pitfall 5: Dedup key collision for Canvas assignments without `due_at` (SYNC-FIX-04 — hypothesized root cause)
**What goes wrong:** Phase description says "only 1 deadline per course." Reading `src/services/deadline.py::aggregate_and_dedup` Phase 1 (Canvas assignments): `due_str = str(assignment.get("due_at", ""))`. When `due_at` is actually `None` (Python object), `str(None) == "None"` — which is truthy! The code then proceeds, and `due_date_str = due_str[:10] = "None"`. Every un-dated assignment gets `compute_dedup_key(course.code, title, "None")` and then hits `datetime.fromisoformat("None...")` → `ValueError` → `continue`. So actually only the first dated assignment persists. BUT: if there's also code elsewhere that doesn't check, all un-dated rows collapse on dedup_key (same date string).
  Actual bug found: `if not title or not due_str:` — `due_str = "None"` passes this check (truthy). Then `fromisoformat("None")` throws `ValueError` → `continue`. So un-dated assignments are silently dropped. Only assignments with real `due_at` make it through. If a course has only 1 assignment with `due_at` set, result is 1 deadline.
**Why it happens:** `dict.get("due_at", "")` default of empty string is never used because Canvas returns `"due_at": null` (JSON null → Python None) → `str(None)` is `"None"`.
**How to avoid:** Change to `due_raw = assignment.get("due_at"); if not isinstance(due_raw, str) or not due_raw: continue` before any further processing. Same fix in Phase 2 (Ed Lessons). Also applies to `sync_deadlines` filter `if lesson_item.get("due_at")` which is already correct (non-stringified truthy check).
**Warning signs:** `SELECT course_id, COUNT(*) FROM unified_deadlines GROUP BY course_id` shows exactly 1 per course despite Canvas having many assignments; `canvas_request` logs show the assignments endpoint returning 10+ rows per course.

### Pitfall 6: "Final Exam for: X" concession courses appear as real courses (SYNC-FIX-05 — root cause)
**What goes wrong:** Canvas returns concession-exam "shell" courses with names like `"Final Exam for: COMP2017 Systems Programming"`. These have a valid `course_code` (COMP2017) and `semester` extractable from context, so `extract_course_code` returns COMP2017 and the shell is linked as a duplicate course or overrides the real one.
**Why it happens:** No filter on Canvas course name. The `extract_course_code` regex just finds the first `[A-Z]{4}\d{4}` pattern in any name.
**How to avoid:** Add a filter in `link_courses` (or in `CanvasAdapter.get_courses`): skip any canvas course whose name matches `/^Final Exam for:/i` or `/concession/i`. Document filter in `src/services/course_linking.py`. Alternatively use `enrollment_type` filter on Canvas — concession shells usually have a different enrollment term.
**Warning signs:** User-visible course list shows duplicate entries or "Final Exam for: ..." entries; `SELECT code, name FROM courses WHERE user_id=...` shows shell rows.

### Pitfall 7: Integration test flakiness from live USYD CDN (SYNC-FIX-01 validation)
**What goes wrong:** Any integration test that hits `https://sydney.edu.au` in CI will fail when (a) network is unavailable, (b) CDN rate limits, (c) USYD changes HTML.
**How to avoid:** Two-tier testing:
  - Unit tests: parse locally cached HTML fixtures (check into `tests/fixtures/usyd/COMP2017_2026-S1.html`). Run in CI.
  - Integration test: live fetch, gated behind `RUN_LIVE_USYD_TESTS=1` env var. Run only on-demand or weekly canary.
**Warning signs:** Intermittent CI failures tied to USYD responses.

### Example 1: Wire up Unit Outline URL resolution in `sync_all_courses` (SYNC-FIX-01)
```python
# File: src/sync/courses.py (modification to _upsert_courses)
# Source: TRD §2.2 canvas_get_unit_outline_url + existing CanvasAdapter.get_tabs/get_external_tool
async def _resolve_unit_outline_url(
    adapter: CanvasAdapter, canvas_course_id: str
) -> str | None:
    """Resolve USYD Unit Outline URL via Canvas tabs → external_tools flow.

    Returns None if no Unit Outline tab exists or tool has no URL.
    """
    try:
        tabs = await adapter.get_tabs(canvas_course_id)
    except Exception:
        logger.warning("outline_url_tabs_failed", course_id=canvas_course_id)
        return None

    outline_tab = next(
        (
            t
            for t in tabs
            if isinstance(t.get("label"), str)
            and str(t["label"]).startswith("Unit Outline")
        ),
        None,
    )
    if outline_tab is None:
        return None

    tab_id = str(outline_tab.get("id", ""))
    prefix = "context_external_tool_"
    if not tab_id.startswith(prefix):
        return None
    tool_id = tab_id.removeprefix(prefix)

    try:
        tool = await adapter.get_external_tool(canvas_course_id, tool_id)
    except Exception:
        logger.warning("outline_url_tool_failed", course_id=canvas_course_id)
        return None

    custom_fields = tool.get("custom_fields")
    if not isinstance(custom_fields, dict):
        return None
    url = custom_fields.get("url")
    if isinstance(url, str) and url.startswith("https://sydney.edu.au/units/"):
        return url
    return None
```

Call site in `_upsert_courses`:

# After existing upsert block, before session.flush()

## Open Questions

1. **Should `unit_outline_url` resolution run on every course sync, or one-time?**
   - What we know: URL rarely changes per semester (TRD §2.2 — "Unit Outline 每学期变化一次")
   - What's unclear: Whether to re-fetch when URL already set (covers the case where prior value was wrong)
   - Recommendation: Fetch only if `unit_outline_url IS NULL`, with a one-time backfill migration or admin re-sync endpoint to clear stale URLs.

2. **SYNC-FIX-04 hypothesis confirmation — is `str(None)` really the bug?**
   - What we know: Code reads `due_str = str(assignment.get("due_at", ""))`. If upstream JSON has `"due_at": null`, Python gets `None`, `str(None) == "None"`. Subsequent `fromisoformat("None...")` raises and `continue` fires.
   - What's unclear: Whether Canvas actually returns `null` for ungraded items, or omits the field entirely (then default `""` would apply).
   - Recommendation: Run a live probe against sandbox Canvas course to confirm before writing the fix. If the bug is different, the fix-shape is similar but the check changes.

3. **Should we preserve assignments without due dates?**
   - What we know: Current code silently drops them; they'd show up as "undated assessments" in the dashboard.
   - What's unclear: Whether the product wants these as "no-due-date" placeholders or truly excluded.
   - Recommendation: Exclude for now (matches current `unified_deadlines` contract which has non-null `due_date`); surface via `Grade` table instead (they already land there).

4. **Does Ed Discussion course name format actually drop semester?**
   - Assumption based on: TRD §11.1 shows Ed course IDs but doesn't show Ed course name format.
   - What's unclear: Real format without live Ed token.
   - Recommendation: Add log output in one sync cycle (`logger.info("ed_courses_seen", names=[...])`) to capture the real formats before committing to the fallback design.
