<objective>
Extend the existing `GET /sync/status` response with a new `per_platform_counts` field that groups domain-level record counts under their source platform (`canvas` for grades+deadlines, `ed` for discussions). The existing `last_sync.results` field stays untouched for backwards compatibility. Regenerate frontend OpenAPI types so plan 33-07 (SuccessStep platform rows) can consume them with full type safety.

Purpose: ONBD-01 requires per-platform progress display. The `/sync/status` endpoint already exists and returns counts by domain — but the UX needs them grouped by platform. Doing the grouping server-side (vs. inferring on the frontend) keeps the platform→domain mapping in one place and survives future domain additions.
Output: Schema field, route logic, regenerated frontend types, and a unit test.
Success Criteria Contribution: ROADMAP success criterion #2 (per-domain sync progress). Plan 33-07 consumes this output.
</objective>

```python
DOMAIN_TO_PLATFORM = {
    "grades": "canvas",
    "deadlines": "canvas",
    "discussions": "ed",
}

# After computing last_sync_results dict (existing code):
if last_sync is not None:
    canvas_grades = last_sync_results.get("grades", 0)
    canvas_deadlines = last_sync_results.get("deadlines", 0)
    ed_discussions = last_sync_results.get("discussions", 0)
    per_platform_counts = PerPlatformCounts(
        canvas=CanvasPlatformCounts(
            grades=canvas_grades,
            deadlines=canvas_deadlines,
            total=canvas_grades + canvas_deadlines,
        ),
        ed=EdPlatformCounts(
            discussions=ed_discussions,
            total=ed_discussions,
        ),
    )
else:
    per_platform_counts = None
```
