    Since `@playwright/test` is NOT installed until P04 (per RESEARCH.md version verification), implement the measurement as a **standalone TypeScript runner** using Node's `fetch` + `AbortSignal.timeout`. No Playwright dependency.

    Create `frontend/tests/e2e/perf/measure-coldstart.ts` — a one-shot Node script that:
    1. Reads `NEXT_PUBLIC_API_URL` from env.
    2. Makes a single timed request to `${URL}/healthz` with a 30s timeout.
    3. Prints `SAMPLE_MS=<n>` on stdout and exits 0 on success, exit 1 on timeout/failure.
    4. Does NOT loop — looping is the workflow's job (via matrix + GH Actions `sleep`).

    Target content:
    ```typescript
    // Standalone Node 20+ script. Run via `pnpm exec tsx measure-coldstart.ts`
    // or bare `node --experimental-strip-types measure-coldstart.ts` (Node 22.6+).
    // Also executable by GH Actions via a small `steps:` invocation (task 2).

    const RAILWAY_URL = process.env.NEXT_PUBLIC_API_URL;
    if (!RAILWAY_URL) {
      console.error("NEXT_PUBLIC_API_URL not set");
      process.exit(1);
    }

    const TIMEOUT_MS = 30_000;
    const start = Date.now();

    try {
      const resp = await fetch(`${RAILWAY_URL}/healthz`, {
        signal: AbortSignal.timeout(TIMEOUT_MS),
      });
      const elapsed = Date.now() - start;
      if (!resp.ok) {
        console.error(`FAIL status=${resp.status} elapsed=${elapsed}`);
        process.exit(1);
      }
      console.log(`SAMPLE_MS=${elapsed}`);
      process.exit(0);
    } catch (e) {
      const elapsed = Date.now() - start;
      console.error(`FAIL error=${(e as Error).message} elapsed=${elapsed}`);
      process.exit(1);
    }
    ```

  <action>
    Create `.github/workflows/railway-coldstart-measure.yml`:

    ```yaml
    name: Railway Cold-Start Measurement

    on:
      workflow_dispatch:
        inputs:
          sample_count:
            description: "Number of samples (N)"
            required: false
            default: "10"
          idle_minutes:
            description: "Minutes between samples to force cold-start"
            required: false
            default: "15"

    jobs:
      measure:
        runs-on: ubuntu-latest
        timeout-minutes: 180  # N=10 × 15 min idle + overhead ceiling
        defaults:
          run:
            working-directory: frontend
        env:
          NEXT_PUBLIC_API_URL: ${{ secrets.NEXT_PUBLIC_API_URL }}
        steps:
          - uses: actions/checkout@v4
          - uses: pnpm/action-setup@v4
            with:
              version: 10
          - uses: actions/setup-node@v4
            with:
              node-version: "22"
              cache: pnpm
              cache-dependency-path: frontend/pnpm-lock.yaml
          - run: pnpm install --frozen-lockfile

          - name: Run N spaced samples
            shell: bash
            run: |
              N="${{ github.event.inputs.sample_count }}"
              IDLE_MIN="${{ github.event.inputs.idle_minutes }}"
              SAMPLES=()
              for i in $(seq 1 "$N"); do
                echo "--- Sample $i of $N ---"
                OUT=$(pnpm exec tsx tests/e2e/perf/measure-coldstart.ts)
                MS=$(echo "$OUT" | grep -oE "SAMPLE_MS=[0-9]+" | cut -d= -f2)
                if [ -z "$MS" ]; then
                  echo "Sample $i failed"; exit 1
                fi
                SAMPLES+=("$MS")
                echo "Sample $i = ${MS}ms"
                if [ "$i" -lt "$N" ]; then
                  echo "Idle ${IDLE_MIN} min..."
                  sleep $((IDLE_MIN * 60))
                fi
              done
              echo "RAW_SAMPLES=${SAMPLES[*]}" | tee samples.txt

          - name: Upload samples artifact
            uses: actions/upload-artifact@v4
            with:
              name: coldstart-samples
              path: frontend/samples.txt
    ```

    The job runs on `workflow_dispatch` only (manual invoke). Default N=10 samples × 15 min idle = ~150 min total, under GH Actions free-tier job limit (6h) but well past any single sprint window. The user invokes via GitHub UI → Actions → "Railway Cold-Start Measurement" → "Run workflow".

    ```yaml
    name: Railway Warmup

    # DISABLED BY DEFAULT — only runs on workflow_dispatch until the cold-start
    # measurement report (`coldstart-report.md`) justifies enabling the schedule.
    #
    # To enable: uncomment the `schedule:` block below AND remove the comment
    # on the next line.
    on:
      workflow_dispatch:
      # schedule:
      #   - cron: "*/10 * * * *" # every 10 minutes

    jobs:
      warmup:
        runs-on: ubuntu-latest
        timeout-minutes: 2
        env:
          RAILWAY_URL: ${{ secrets.NEXT_PUBLIC_API_URL }}
        steps:
          - name: Ping /healthz
            run: |
              if [ -z "$RAILWAY_URL" ]; then
                echo "NEXT_PUBLIC_API_URL secret not configured"
                exit 1
              fi
              curl -fsS --max-time 15 "$RAILWAY_URL/healthz" > /dev/null
              echo "Warmup ping OK"
    ```

    Key contract: `schedule:` is **commented out** until the user activates it. `workflow_dispatch` allows manual testing of the warmup job itself (the user can invoke it once to prove it works before uncommenting `schedule`).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GH Actions runner → Railway `/healthz` | Public unauthenticated endpoint; no credentials crossed |
| GH Actions → repo secrets | `NEXT_PUBLIC_API_URL` read from encrypted secret store |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-07 | Denial of Service | Warmup cron attacker-controllable via PR | mitigate | `schedule:` only fires from default branch; PRs cannot change the schedule on the live workflow. Cron interval (10 min) is fixed, not injectable from request data. |
| T-38-08 | Information Disclosure | Measurement logs leaking backend URL | accept | `NEXT_PUBLIC_API_URL` is, by design, public (Next.js exposes it to the browser). GH Actions logs showing the URL add no new exposure. |
| T-38-09 | Denial of Service | Measurement workflow consuming GH Actions minutes | accept | Workflow is `workflow_dispatch` only — user-invoked. 150 min × <1/month usage pattern is well under free-tier budget. |
| T-38-10 | Tampering | Attacker invoking `railway-warmup.yml` `workflow_dispatch` via PR | mitigate | `workflow_dispatch` requires `actions: write` permission — only collaborators can trigger. PRs from forks cannot invoke. |
</threat_model>
