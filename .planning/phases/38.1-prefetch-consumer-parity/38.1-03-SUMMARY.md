# Phase 38.1 Plan 03: Predict + Timetable Prefetch Parity Summary

**One-liner:** Hoisted users/me + study-rec prefetches in Predict (outside courseIds guard) and added N-fanout of courseOptions.detail to Timetable via await-then-fanout two-step pattern, flipping both cases in prefetch-consumer-parity.test.ts from RED to GREEN.

## Changes

### Predict (`frontend/app/[locale]/(dashboard)/predict/page.tsx`)

- **Imports added:** `userOptions` from `@/hooks/use-user`, `studyRecOptions` from `@/hooks/use-study-recommendations`.
- **Type aliases added:** `UserMeResponse`, `StudyRecResponse` (both from `paths[...]`).
- **Run body restructure:**
  - Step 1 unchanged: `await queryClient.fetchQuery({...gpaOptions.report(), ...})` — awaited fetchQuery count preserved at 1.
  - Step 2a (NEW): `topLevelPrefetches` array hoisted ABOVE the `if (courseIds.length > 0)` guard. Contains 2 entries:
    - `userOptions.me()` → `api.get("users/me").json<UserMeResponse>()` + `.catch(wrapSentry("users", userId))`
    - `studyRecOptions.latest()` → `api.get("ai/study-recommendations").json<StudyRecResponse>()` + `.catch(wrapSentry("study-rec", userId))`
  - Step 2b: existing N-fanout (detail + roi) preserved verbatim. If-branch now awaits `Promise.allSettled([...topLevelPrefetches, ...fanoutPrefetches])`; else-branch (gpa failure / empty courses) awaits `Promise.allSettled(topLevelPrefetches)` so user-me / study-rec still hydrate.
- **Waterfall invariant preserved:** awaited fetchQuery count = 1 (gpa only).

### Timetable (`frontend/app/[locale]/(dashboard)/timetable/page.tsx`)

- **Type alias added:** `CourseDetailResponse` from `paths["/courses/{id}"]...`.
- **Imports unchanged** — `courseOptions` already imports both `.list` and `.detail`.
- **Run body restructure — single-wave Promise.allSettled(4) → two-step pattern:**
  - Step 1 (NEW): `await queryClient.fetchQuery({...courseOptions.list(), queryFn: () => api.get("courses").json<CoursesResponse>()})` — courseIds derived via `coursesResp.data.map((c) => c.id)`; try/catch with `wrapSentry("courses", userId)(error)` for real rejection propagation.
  - Step 2: `Promise.allSettled(prefetches)` where `prefetches` contains 3 top-level queries (sessions, weeks, deadlines-list) + `...courseIds.map((id) => queryClient.prefetchQuery({...courseOptions.detail(id), queryFn: () => api.get(\`courses/${id}\`).json<CourseDetailResponse>()}).catch(wrapSentry("course-detail", userId, { courseId: id })))`.
- **Graceful degrade:** If Step 1 fails, courseIds stays `[]`, N-fanout is empty, but 3 top-level prefetches still fire (D-B4 silent degrade).
- **Waterfall invariant:** awaited fetchQuery count = 1 (courses.list only).
- **No roiOptions:** confirmed via grep `! grep -qE 'roiOptions' timetable/page.tsx` — Predict-specific per PATTERNS.md §2 pp.297.
