# Phase 38.1 — Server-Prefetch ↔ Client-Consumer Parity (Gap Closure)

## Phase goal

Close the Phase 38 HUMAN-UAT Truth #2 gap surfaced during production verification on 2026-04-21: **eliminate SkeletonCard flash on hard-refresh of any `force-dynamic` dashboard page**. The root cause is an incomplete server-prefetch list — each page's `createPrefetchedPage({ run })` prefetches a subset of the queries that the client component actually consumes, so any hard-refresh produces `isLoading: true` for the missing queries and flashes the per-variant `SkeletonCard`.

## Why this is 38.1 not 39

- Phase 38 Success Criterion #2 + PERF-01 explicitly require "first paint shows real data — no skeleton on cached-auth revisit, 6 pages".
- Phase 38 verification (`38-VERIFICATION.md:Truth #2`) marked the criterion `HUMAN_NEEDED` and deferred to the 38-04 Playwright baseline capture — which is still pending. Today's production UAT is the human naked-eye observation that would have happened at that checkpoint; it fails the criterion.
- Fix is scoped (edit the 5 `force-dynamic` page.tsx prefetch lists; zero architecture change), reuses `createPrefetchedPage` HOF verbatim, and flows from the same design contract.
- Treating as 38.1 keeps the Phase 38 LEARNINGS / PATTERNS / VALIDATION lineage intact — the fix is a completion, not a new initiative.

## Production evidence (2026-04-21)

Hard-refresh (Cmd+Shift+R) observation on `https://uni-board-r1ckyins-projects.vercel.app` after PR #96 (sidebar `prefetch={true}`) deployed:

| Hard-refresh target | Skeleton flash on target page | Skeleton flash on subsequent sidebar nav |
|---|---|---|
| Dashboard | ✅ flashes (`ProfileCard`, `RecentActivity` variants) | ❌ none |
| Timetable | ✅ flashes (timetable grid / course-detail fanout) | ❌ none |

Pattern: **only the hard-refreshed page flashes** — subsequent client-side nav hits the QueryClient cache populated by whichever pages fill the cross-page queries (header avatar, notifications badge). The hard-refreshed page starts from a cold QueryClient; any `useQuery` consumer whose key is not in the HydrationBoundary dehydrated state renders `isLoading: true` → `SkeletonCard`.

## Scope

- Audit all 6 `force-dynamic` dashboard pages for consumer↔prefetch parity
- For each gap, add the missing `prefetchQuery` / `fetchQuery` call to the page's `run()` function (reusing existing hooks' `queryOptions` factories + `wrapSentry`)
- Handle N-fanout (Timetable course detail) via post-`courses.list` fetchQuery loop
- Introduce a static invariant test (grep-level or AST-level) that asserts every client `useQuery*` hook used by a dashboard page has a matching `prefetchQuery`/`fetchQuery` call in the page's `run()` — guards against regression
- Update Phase 38 HUMAN-UAT #1 from pending → pass once verified in production

## Out of scope

- Architectural changes to `createPrefetchedPage` HOF (it is correct; the gap is in the caller's `run` body)
- Removing `force-dynamic` (Phase 38 design contract; out-of-scope for gap closure)
- Moving cross-page queries (`useCurrentUser`, `useNotifications`) into dashboard layout — deliberate deferral; a parallel approach but larger blast than needed for this gap
- Playwright pixel-diff baseline capture (Phase 38 Task 38-04 Step 5, still gated on Supabase credential checkpoint)

## Design constraints (from Phase 38)

- **PATTERNS.md corr. #1 / D-B4**: "Hydrate exactly what the consumer reads." This is the exact invariant we are restoring.
- **Silent degrade**: reuse `wrapSentry("<label>", userId)` on every `.catch()`. Tag convention is `phase: "38"` for continuity (the fix belongs to Phase 38's design contract).
- **Parallelism**: all new prefetches go into `Promise.allSettled` (never awaited serially)
- **QueryKey parity**: use the hook's exported `queryOptions` factory (`{ ...xxxOptions.yyy() }` spread) — do NOT hand-roll keys (PATTERNS.md §Query-Key Parity)
- **Fresh QueryClient per request**: already enforced by `getServerQueryClient` — do not introduce module-scope mutations

## Success criteria (derived from CONTEXT)

1. Hard-refresh each of Dashboard / Courses / Deadlines / Predict / Digest / Timetable — zero `SkeletonCard` visible above the fold (naked eye)
2. All `force-dynamic` page.tsx prefetch lists cover 100% of client-side `useQuery*` consumers of those pages (auditable)
3. Static invariant test added + passing: every client `useQuery` consumed by a `force-dynamic` page has a matching `prefetchQuery`/`fetchQuery` in the page's `run`
4. No regression in automated tests (vitest + Playwright smoke)
5. Sentry tag convention preserved (`phase: "38"`, `operation: "rsc_prefetch"`, `query: <label>`) for new prefetches
6. Phase 38 HUMAN-UAT item #1 (skeleton-flash on cached-auth revisit) flipped to `passed` post-deploy
