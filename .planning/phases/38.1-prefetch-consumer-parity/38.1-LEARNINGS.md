# Phase 38.1 Learnings: Server-Prefetch ↔ Client-Consumer Parity (Gap Closure)

## Decisions

### Sentry label "users" (not "user-me") for userOptions.me

Use the first queryKey segment of `userOptions.me()` per `deriveQueryLabel` rule (create-prefetched-page.tsx:54-57), not a descriptive alias. Aligns the explicit `.catch(wrapSentry(...))` tag with the QueryCache `onError` subscriber's auto-derived tag, so both Sentry channels produce identical `tags.query` values for aggregation.

**Rationale:** If a query fails via both the per-call catch AND the cache subscriber, divergent tags would split one logical failure across two Sentry events.
**Source:** 38.1-02-SUMMARY.md §decisions, 38.1-03-SUMMARY.md §decisions

### Digest labels disambiguated via kebab-case suffix

`digest-latest` / `digest-history` because both factories share queryKey first segment `digest`. Matches Phase 38 precedent (`deadlines-upcoming` / `deadlines-list`).

**Rationale:** First-segment rule breaks when one factory has multiple queries; kebab-case disambiguation preserves aggregation while maintaining per-query visibility.
**Source:** 38.1-02-SUMMARY.md §decisions

### Sentry phase tag stays "38" (not "38.1")

Gap-closure prefetches carry the parent phase's tag, not the sub-phase number. Zero `phase: "38.1"` in codebase; the frozen `create-prefetched-page.tsx:38` `PHASE_TAG = "38"` is the single source of truth.

**Rationale:** Gap closure belongs to Phase 38's design contract — post-hoc sub-phases should not fragment observability taxonomy. Sentry aggregation must see Phase 38 + 38.1 prefetch failures as one metric family.
**Source:** 38.1-CONTEXT.md §Design constraints, 38.1-02-SUMMARY.md §decisions, 38.1-03-SUMMARY.md §decisions

### Predict hoists topLevelPrefetches outside the courseIds guard

`topLevelPrefetches` array (`userOptions.me` + `studyRecOptions.latest`) declared ABOVE the `if (courseIds.length > 0)` block. Both if-branch AND else-branch await `Promise.allSettled(topLevelPrefetches)`.

**Rationale:** If `/gpa` returns an error or empty courses, the else-branch must STILL hydrate user-identity + study-rec, otherwise Predict's hard-refresh still flashes skeleton in the gpa-failure path. PATTERNS.md §5 fact #7 documents this as load-bearing.
**Source:** 38.1-03-SUMMARY.md §decisions, 38.1-PATTERNS.md §5

### Timetable two-step pattern: fetchQuery for Step 1, prefetchQuery for Step 2

Step 1: `await queryClient.fetchQuery(courseOptions.list())` — uses fetchQuery (rejects on error so wrapSentry fires for real). Step 2: `Promise.allSettled` over 3 top-level parallel + N × `courseOptions.detail(id)` fanout via `coursesResp.data.map((c) => c.id)`.

**Rationale:** `prefetchQuery` always resolves (TanStack v5 contract), which would swallow the list-query error and produce empty courseIds silently. `fetchQuery` propagates rejection so the try/catch + wrapSentry path fires correctly.
**Source:** 38.1-03-SUMMARY.md §decisions, 38.1-PATTERNS.md §2

### Timetable courseIds derived from .id not .code

`coursesResp.data.map((c) => c.id)` — the detail endpoint is `/courses/{id}`, not `/courses/{code}`. Verified via hooks/use-courses.ts `api.get(\`courses/${id}\`)`.

**Rationale:** Dashboard's nearest-course lookup at page.tsx:107-111 uses `.find((c) => c.code === nearestCode)?.id` to translate — confirming `id` is the URL parameter.
**Source:** 38.1-03-SUMMARY.md §decisions

**Rationale:** The test output literally names each missing factory per page ("Dashboard has unprefetched consumers: useNotifications (expected prefetch via notificationOptions.list), ..."). This replaces the need for executor-side specification — the executor just makes the test green.

## Lessons

### Sidebar-nav fix masked the hard-refresh gap

PR #96 (`prefetch={true}` on Sidebar Links) fixed the sidebar click-through experience by forcing Next.js Link prefetch on `force-dynamic` routes. But the underlying consumer-parity gap was still there — PR #96 just warmed the client QueryClient cache so cross-page queries like `useCurrentUser` / `useNotifications` were filled by the first visited page. Hard-refresh starting from an empty QueryClient re-exposed the gap for the target page only.

**Context:** Two root causes conflated under one symptom until production UAT 2026-04-21 isolated them. Pattern: a symptom that disappears on second visit but reappears on hard-refresh points to HydrationBoundary missing cache coverage, not navigation prefetch.
**Source:** .planning/debug/sidebar-nav-skeleton-stall.md §Current Focus §hypothesis

### Regex tests over source code need a stripComments() pre-pass

Timetable's page.tsx header comment literally contained the string `courseOptions.detail` in a documentation line. A naive `pageSource.includes("courseOptions.detail")` check would have returned `true` for a page that genuinely lacks the prefetch — producing false-GREEN.

**Context:** The fix is a regex pre-pass stripping `/* ... */` blocks and `// ...` line comments before the includes check. Add to any future static-analysis test that greps source strings.
**Source:** 38.1-01-SUMMARY.md §Deviations from PATTERNS.md §7 template #1

### `useQueries({ queries: [...factory.detail(id)] })` needs reverse-scan

The conventional hook-call regex `\buse[A-Z]\w*\(` doesn't see `courseOptions.detail(c.id)` when it's inlined inside a `useQueries` call instead of a `useCourseDetail()` direct call. The RED test would report "no missing prefetch" for Timetable because the regex cannot map the inline factory back to the hook name.

**Context:** Solved via a second pass scanning consumer source for `xxxOptions.yyy(` matches and reverse-mapping via FACTORY_TO_HOOK to produce the human-readable hook name in the failure message.
**Source:** 38.1-01-SUMMARY.md §Deviations from PATTERNS.md §7 template #2

### Hard-refresh cache-miss is a per-page signal

"The hard-refreshed page flashes; subsequent client-nav pages don't" is a specific diagnostic pattern indicating the page's server prefetch is a strict subset of its client consumers. Cross-page warmth (shared header/sidebar queries) masks the gap on subsequent navigations, but the target page starts from a cold QueryClient.

**Context:** In debugging, always test both hard-refresh AND client-side navigation of every page, not just one or the other. A symptom on one path but not the other localises the fix layer (RSC vs client).
**Source:** .planning/debug/sidebar-nav-skeleton-stall.md §evidence

### Pre-existing next-intl test failures surfaced but deferred

25 test failures in `__tests__/course-detail/`, `__tests__/deadlines/`, `__tests__/layout/`, `__tests__/setup/` — all share root cause `No intl context found` (tests need `NextIntlClientProvider` wrapper). Verified baseline on commit `9be33b2` before any 38.1 edit.

**Context:** Not a regression from 38.1; documented in `deferred-items.md` for future cleanup. Candidate for a dedicated "test-harness-next-intl-fix" phase or seed — probably SEED-002.
**Source:** 38.1-03-SUMMARY.md §Full Vitest Regression Check, deferred-items.md

## Patterns

### Gap-closure phase via TDD RED→GREEN across parallel plans

Plan 01 commits a failing test (Wave 1). Plans 02 + 03 edit disjoint source files in parallel worktrees (Wave 2) to flip cases GREEN. Natural wave structure, zero files_modified overlap = safe parallel execution with no merge conflicts.

**When to use:** Any gap-closure phase where (a) the gap is mechanically testable, (b) the fixes can be partitioned by file, and (c) the test output can name each missing piece precisely. Converts a single-plan sequential fix into a parallel TDD pipeline.
**Source:** 38.1-01-SUMMARY.md §Outcome, 38.1-02-SUMMARY.md §Test Outcomes, 38.1-03-SUMMARY.md §Verification Results

### Static-invariant regression test as forcing function

`prefetch-consumer-parity.test.ts` is authoritative — if any future PR adds a consumer hook without also adding its prefetch, CI fails with a literal message pointing to the missing factory. More durable than line-level code review because it scales to every future PR touching the 6 pages.

**When to use:** Any architectural invariant that's cheap to express as a grep-level or AST-level assertion over a bounded file set. Prefer this over reviewer checklists for invariants that must not drift.
**Source:** 38.1-VERIFICATION.md Truth #3, 38.1-PATTERNS.md §7

### Hoisted top-level prefetches outside conditional guard

When a page has conditional data (e.g., per-course fanout dependent on list length), always-needed queries (user identity, global widgets) must be hoisted ABOVE the conditional block so failure paths still hydrate the user-identity layer.

**When to use:** Any RSC page where some queries are universally consumed and others are conditionally needed. The conditional branch must `await Promise.allSettled([...topLevelPrefetches, ...conditionalPrefetches])`, and the else-branch must still `await Promise.allSettled(topLevelPrefetches)`.
**Source:** 38.1-03-SUMMARY.md §Changes §Predict, 38.1-PATTERNS.md §5

### Two-step await-then-fanout for N-parallel detail queries

Step 1: `await fetchQuery(listOptions)` — derives ids from response. Step 2: `Promise.allSettled([...topLevelPrefetches, ...ids.map(id => prefetchQuery(detailOptions(id)))])`. Use `fetchQuery` for Step 1 (rejects on error for wrapSentry), `prefetchQuery` for Step 2 fanout (always resolves, with individual `.catch(wrapSentry(label, userId, { id }))`).

**When to use:** Any page that needs to prefetch N detail records where N is computed from a list query. Preserves waterfall invariant at 1 awaited fetchQuery (the list) while parallelising detail fetches.
**Source:** 38.1-03-SUMMARY.md §Changes §Timetable, 38.1-PATTERNS.md §2

### Three-bucket hook classification with no-unknown-bucket audit

HOOK_TO_FACTORY (must be prefetched) / MUTATION_HOOKS (exempt) / IGNORED_HOOKS (React stdlib + framework + non-data). Any fourth-bucket hook name fails the no-unknown-bucket audit, forcing explicit classification.

**When to use:** Any static test over a finite hook-usage domain where silent drift is the failure mode. Converts "we think the list is complete" into "the test fails until the list is complete."
**Source:** 38.1-01-SUMMARY.md §Test Harness Design, 38.1-01-SUMMARY.md §IGNORED_HOOKS Allowlist Rationale

### Tag continuity across sub-phases

Gap-closure sub-phases retain the parent phase's observability identifier. Phase 38.1 prefetches carry `phase: "38"` not `phase: "38.1"` so Sentry aggregation groups Phase 38 failures + 38.1-introduced failures as one metric family.

**When to use:** Any sub-phase that completes / gap-closes a parent's design contract without introducing new primitives. If the sub-phase introduces a new product surface, tag divergence is appropriate; for pure completion work, keep continuity.
**Source:** 38.1-CONTEXT.md §Design constraints

### useQueries inline-factory pattern is pervasive

Two pages (Timetable, Predict) use `useQueries({ queries: [...ids.map(id => factory.detail(id))] })` instead of a loop of `useDetail(id)` calls. Without the FACTORY_TO_HOOK reverse-scan deviation, the RED test's failure messages would have been misleading (reporting "no missing prefetch" or naming the wrong hook).

**Impact:** Plan 01 had to extend PATTERNS.md §7's template with a second scan pass. Lesson: any static test over hook usage must account for both direct `useFoo()` calls AND inline factory usage in `useQueries`.
**Source:** 38.1-01-SUMMARY.md §Deviations from PATTERNS.md §7 template

### Sentry label convention divergence (PATTERNS vs PLAN)

PATTERNS.md §1 suggested `"user-me"` for `userOptions.me()`. PLAN.md overrode with `"users"` citing `deriveQueryLabel` rule. Executor followed PLAN.md.

**Impact:** No defect surfaced, but it flagged an inconsistency in the phase's own contract. Resolution: documented in 38.1-02-SUMMARY.md §Deviations. For future gap-closure phases — PATTERNS.md should either mirror PLAN.md decisions or explicitly flag suggested-vs-authoritative.
**Source:** 38.1-02-SUMMARY.md §PLAN-vs-PATTERNS label divergence

Phase 38.1 is pure backend (edit server `run` callbacks — zero UI change, zero new component). But the gate's keyword grep matched "dashboard" / "page" in the phase goal, threatening to block plan-phase with a UI-SPEC demand.
