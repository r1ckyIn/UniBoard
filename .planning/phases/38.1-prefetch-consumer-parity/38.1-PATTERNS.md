## Executive summary for the planner

Phase 38 shipped the architecture; 38.1 only edits the **contents of the `run` callback** in existing page.tsx files. There is **no new HOF, no new helper, no new Sentry convention, no new queryClient surface area**. Executors should:

1. Open the page.tsx being modified
2. Identify the missing prefetch (per audit table below)
3. Add a `queryClient.prefetchQuery({...xxxOptions.yyy(), queryFn: () => api.get("…").json<T>()}).catch(wrapSentry("<label>", userId))` into the existing `Promise.allSettled([...])` — or open a new `Promise.allSettled` if the run body is currently a single awaited prefetch
4. Keep tags `{ phase: "38", operation: "rsc_prefetch", query: <label> }` — **do not invent `phase: "38.1"`**; the gap closure belongs to Phase 38's design contract (per CONTEXT.md §Design constraints)

The **only net-new file** is the static-invariant vitest at `frontend/__tests__/rsc/prefetch-consumer-parity.test.ts`. Its direct analog is the existing `dashboard-prefetch.test.ts` which already uses `readFileSync` + regex to assert a static property over page.tsx source. 38.1 generalises that harness across all 6 `force-dynamic` pages.

**Analog excerpt — N-fanout pattern from Predict (`frontend/app/[locale]/(dashboard)/predict/page.tsx:56-99`):**

```typescript
run: async ({ queryClient, accessToken, userId }) => {
  const api = await getServerApiClient(accessToken);

  // Step 1: await source list (N source of truth)
  let courseIds: string[] = [];
  try {
    const gpaReport = await queryClient.fetchQuery({
      ...gpaOptions.report(),
      queryFn: () => api.get("gpa").json<GpaReportResponse>(),
    });
    courseIds = gpaReport.data.courses.map((c) => c.course_id);
  } catch (error) {
    wrapSentry("gpa", userId)(error);
  }

  // Step 2: full N-fanout — ALL N × detail in ONE Promise.allSettled
  if (courseIds.length > 0) {
    const prefetches: Promise<unknown>[] = [
      ...courseIds.map((id) =>
        queryClient
          .prefetchQuery({
            ...courseOptions.detail(id),
            queryFn: () =>
              api.get(`courses/${id}`).json<CourseDetailResponse>(),
          })
          .catch(wrapSentry("course-detail", userId, { courseId: id })),
      ),
      // ... roi fanout (Predict-only; omit for Timetable)
    ];
    await Promise.allSettled(prefetches);
  }
},
```

**Executor action — replace Timetable's current single-wave `Promise.allSettled` with a two-step pattern.** Current file awaits 4 parallel prefetches. New shape: await courses.list first (so we get ids), then the remaining 3 top-level queries fan out in parallel with the N-detail fanout.

**Target shape (replace existing `run` body lines 63-93):**

```typescript
run: async ({ queryClient, accessToken, userId }) => {
  const api = await getServerApiClient(accessToken);

  // Step 1: await /courses to get the N courseIds for the N-fanout.
  // fetchQuery rejects on error, so wrapSentry fires here for real.
  let courseIds: string[] = [];
  try {
    const coursesResp = await queryClient.fetchQuery({
      ...courseOptions.list(),
      queryFn: () => api.get("courses").json<CoursesResponse>(),
    });
    courseIds = coursesResp.data.map((c) => c.id);
  } catch (error) {
    wrapSentry("courses", userId)(error);
  }

  // Step 2: top-level independent prefetches + N × course detail fanout.
  const prefetches: Promise<unknown>[] = [
    queryClient
      .prefetchQuery({
        ...timetableOptions.sessions(),
        queryFn: () =>
          api.get("timetable/sessions").json<SessionsResponse>(),
      })
      .catch(wrapSentry("timetable-sessions", userId)),
    queryClient
      .prefetchQuery({
        ...timetableOptions.weeks(),
        queryFn: () =>
          api.get("timetable/weeks").json<WeeksResponse>(),
      })
      .catch(wrapSentry("timetable-weeks", userId)),
    queryClient
      .prefetchQuery({
        ...deadlineOptions.list(),
        queryFn: () => api.get("deadlines").json<DeadlinesResponse>(),
      })
      .catch(wrapSentry("deadlines-list", userId)),
    ...courseIds.map((id) =>
      queryClient
        .prefetchQuery({
          ...courseOptions.detail(id),
          queryFn: () =>
            api.get(`courses/${id}`).json<CourseDetailResponse>(),
        })
        .catch(wrapSentry("course-detail", userId, { courseId: id })),
    ),
  ];
  await Promise.allSettled(prefetches);
},
```

**Load-bearing fact — CoursesResponse `.data` shape.** From `hooks/use-courses.ts` + openapi types, the response envelope is `{ data: Course[], meta: ... }` where each `Course` has `.id` and `.code`. The map above uses `.id` (the detail endpoint is `courses/{id}`). Evidence: existing Dashboard uses `coursesCache?.data.find((c) => c.code === nearestCode)?.id` (page.tsx:L107-111) — so `.data` is the array and `.id` is the key.

**Static analysis constraint:** `await.*\.fetchQuery\b` count in timetable page.tsx becomes **1** (the one awaited courses fetch). This is strictly `<= 2` per PERF-02, so the new invariant applies to Timetable too.

**Do NOT include `roiOptions.course(id)` fanout** — that is Predict-specific (CONTEXT.md: Timetable has no ROI consumer).


### 7. `frontend/__tests__/rsc/prefetch-consumer-parity.test.ts` *(NEW)* — Static Invariant Test

**Role:** static-invariant test (vitest unit, no JSX, no QueryClient — pure fs + regex/AST).
**Data flow:** read filesystem → extract hook imports from page.tsx + client components → cross-reference against prefetch list.
**Closest analog:** `frontend/__tests__/rsc/dashboard-prefetch.test.ts:196-209` — the existing `readFileSync` + regex harness.
**Match quality:** exact (same test harness, generalised to 6 pages × N-hook audit).

**Analog excerpt — static-regex invariant from `dashboard-prefetch.test.ts:196-209`:**

```typescript
// frontend/__tests__/rsc/dashboard-prefetch.test.ts:196-209 (EXISTING — load-bearing template)
it("static analysis: dashboard page.tsx has at most 2 awaited fetchQuery calls (PERF-02 waterfall collapse)", () => {
  const pagePath = resolve(
    __dirname,
    "../../app/[locale]/(dashboard)/page.tsx",
  );
  const source = readFileSync(pagePath, "utf8");
  // Match only the `.fetchQuery(` method shape — the literal `.` before
  // `fetchQuery` excludes `.prefetchQuery` (which is `.pre` + `fetchQuery`),
  // and `\b` ensures `fetchQuery` is a standalone identifier. Without these
  // guards, `await queryClient.prefetchQuery(...)` would be false-counted
  // as a blocking fetch call (WR-02).
  const matches = source.match(/await[^\n]*?\.fetchQuery\b/g) ?? [];
  expect(matches.length).toBeLessThanOrEqual(2);
});
```

**Design notes for the planner:**

1. **Regex-level, not AST-level.** The analog (`dashboard-prefetch.test.ts:L207`) already uses regex. AST parsing (via `@babel/parser` or `typescript`) is overkill for 6 files × ~50 hook imports. The regex `/\b(use[A-Z][a-zA-Z0-9_]*)\s*\(/g` is robust enough — it catches every React hook call. If ambiguity arises (e.g., a non-hook function starting with `use`), add to `MUTATION_HOOKS` or `HOOK_TO_FACTORY` allowlist.

2. **Hook → factory mapping is load-bearing.** The mapping table at the top of the test must be kept in sync with `hooks/use-*.ts`. This is the one piece that requires manual maintenance — call it out in the PLAN.md acceptance criteria so reviewers verify it on PR review. When a new hook is added, the mapping must be extended OR the hook must be added to `MUTATION_HOOKS`. **Failure mode**: new hook gets consumed, not in HOOK_TO_FACTORY, test silently passes. Mitigation: add a second assertion that every `use*` hook imported by `force-dynamic` page consumers is present in either `HOOK_TO_FACTORY` or `MUTATION_HOOKS` — no "unknown" bucket.

3. **Sub-component hook scanning.** If a consumer's sub-component (e.g., `CourseActivityPanel` inside CourseDetailPage) calls `useNotifications()`, the current design only scans the top-level consumer. **Deferral**: accept this as a known limitation for v1; add to CONTEXT.md §Out of scope ("parity test scans top-level consumer only; sub-component leaks out of scope — rare and caught by manual UAT"). Alternative: walk imports recursively via AST — more complex but future-proof. Recommend v1 stays shallow.

4. **File path resolution.** Uses `resolve(__dirname, "../../...")` exactly like the existing test — no new plumbing. Paths are relative to `frontend/__tests__/rsc/`.

5. **Vitest config.** The existing `vitest.config.ts` already picks up `__tests__/rsc/*.test.ts` (see existing `dashboard-prefetch.test.ts` runs). No config change needed.

### Sentry tag convention

**Source:** `frontend/lib/rsc/create-prefetched-page.tsx:38` + `:96-107` + `:140-155`.

```typescript
Sentry.captureException(error, {

    phase: "38",                    // NOT "38.1" — CONTEXT.md §Design constraints

  },

```

**Apply to all new prefetches in 38.1** — via `wrapSentry("<label>", userId[, { courseId }])`.

### Prefetch pattern (ONE canonical shape)

**Source:** `frontend/app/[locale]/(dashboard)/page.tsx:67-87` (Dashboard Wave A) — the Phase 38 reference.

**Canonical call (load-bearing — do NOT deviate):**

```typescript
queryClient
  .prefetchQuery({
    ...xxxOptions.yyy(/* args if any */),   // spread — preserves queryKey parity
    queryFn: () => api.get("<endpoint>").json<ResponseType>(),  // override queryFn
  })
  .catch(wrapSentry("<label>", userId));
```

**Load-bearing invariants:**
1. **Always spread `{ ...xxxOptions.yyy() }`** — never hand-roll queryKey. CONTEXT.md §Design constraints + PATTERNS.md §Query-Key Parity.
2. **queryFn override MUST use `api` from `getServerApiClient(accessToken)`** — NOT the client `api` from `@/lib/api/client.ts` (which reads Zustand → fails on server).
3. **Always `.catch(wrapSentry(...))`** — defense-in-depth alongside the QueryCache onError subscriber. Even though TanStack v5 never rejects from prefetchQuery, the `.catch()` stays for forward-compat (per create-prefetched-page.tsx:L64-67 comment).
4. **Always `.json<T>()` with explicit type parameter** — not bare `.json()` (courses/page.tsx comment at L7 calls this out).

### Parallelism pattern

**Source:** `frontend/app/[locale]/(dashboard)/deadlines/page.tsx:45-58` — canonical parallel shape.

**Rule:** multiple independent prefetches → `Promise.allSettled`. Single prefetch → direct `await queryClient.prefetchQuery(...).catch(...)`. Never `Promise.all` on prefetches (one rejection poisons the whole block — CONTEXT.md §Design constraints + Phase 38 PATTERNS.md).
