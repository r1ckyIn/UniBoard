# Phase 38.2 Plan 01: Frontend Architectural Reversal Summary

Phase 38.2 Plan 01 reverses the `force-dynamic` + `loading.tsx` + diagnostic-breadcrumb architecture from Phase 38/38.1 and restores Next.js 15 router-cache semantics via `experimental.staleTimes.dynamic: 30`, delivering the "skeleton-free on URL entry + zero-latency on re-visit" UX that the parent phases failed to achieve.

## Work Completed

### Task 1: force-dynamic removal (commit 983bd14)

Removed `export const dynamic = "force-dynamic"` from all 6 dashboard pages:
- `page.tsx` (Dashboard)
- `timetable/page.tsx`
- `courses/page.tsx`
- `deadlines/page.tsx`
- `predict/page.tsx`
- `digest/page.tsx`

Routes remain dynamic implicitly because `createPrefetchedPage` calls `supabase.auth.getSession()` which uses `cookies()` via `@supabase/ssr` (RESEARCH R1). No `"auto"` replacement (D-02). No `fetchCache` override (D-03).

### Task 2: loading.tsx deletion (commit c9ddd73)

Deleted `frontend/app/[locale]/(dashboard)/loading.tsx` (31 lines removed). Verified no parent-level `loading.tsx` exists at `app/` or `app/[locale]/` (RESEARCH Pitfall 3 — re-inheritance risk). `SkeletonCard.tsx` itself remains (consumed by `DashboardPage.tsx` and other consumers).

Tradeoff explicitly accepted per D-05: hard refresh now shows ~300ms browser-default spinner (URL bar), no skeleton. Client-side nav preserves "old page visible until new RSC arrives" (Next.js default behavior).

### Task 3: experimental.staleTimes (commit a8870c6)

Added `experimental.staleTimes.dynamic: 30` to `next.config.ts`. Restores v14 router-cache TTL behavior — Next.js 15.0.0 changed the default from 30s to 0s, which defeats the client router cache for auth-gated pages. The `static` default (5 min) remains. MANDATORY per RESEARCH R1/R6 — without this setting, D-01 + D-04 alone do NOT deliver zero-latency re-visit.

Sentry wrapper chain + security headers unchanged.

### Task 4: HOF diagnostic cleanup (commit d9bddac)

- 3 `Sentry.captureMessage` calls (`rsc_hof_entered`, `rsc_hof_completed`, `rsc_prefetch_null_session`)
- `import { headers } from "next/headers"` + `pathHint` variable + all references

Preserved verbatim (D-10, D-11):

- `wrapSentry` export (called from 17 sites across 6 pages)
- `PHASE_TAG = "38"` convention (no `"38.1"` or `"38.2"` anywhere)
- Exactly 3 `Sentry.captureException` call sites
- `createPrefetchedPage` signature unchanged (`Promise<ReactNode>`)
- `PrefetchContext` type export unchanged

All 5 HOF unit tests pass post-cleanup (PLAN anticipated 4 — there are actually 5; all green).
