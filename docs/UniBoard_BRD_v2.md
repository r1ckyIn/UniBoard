## 1. 项目愿景与核心原则

### 1.1 使命

**UniBoard 的唯一使命：帮助学生获得尽可能高的 GPA。**

平台上的一切功能、信息流和交互设计都必须围绕这一核心目标展开。任何与 GPA 提升无关的信息、功能或交互都不纳入开发范围。

### 1.2 核心原则

| 原则 | 说明 |
|------|------|
| **信息精准** | 只推送与学业直接相关的高价值信息，杜绝信息噪声 |
| **只读安全** | 对 Ed Discussion 等社区采取只读策略，绝不发布或回复内容，避免产生垃圾信息 |
| **课件可达** | 学生通过 AI 智能分类，一眼看懂每门课杂乱的文件结构，快速定位所需的学习材料 |
| **零门槛** | 面向非技术类学生设计，使用流程尽可能简单 |

### 1.3 一句话定位

> **UniBoard = Canvas + Ed 的 GPA 最大化仪表盘。** 聚合所有影响你课程成绩的作业deadline、目前GPA和ed discussion关键讨论，只给你对 GPA 有用的信息。

### 1.4 产品远景 — 从信息聚合到学习辅导平台

> 以下为上线后的长期迭代方向，不属于 MVP 范围。

UniBoard 的长期目标是成为一个 **全学科作业辅导平台**。平台的独特优势在于拥有完整的第一手数据链：

1. **Unit Outline**（来自 Canvas 侧边栏跳转链接 → 悉尼大学官网）：精确掌握每门课的评分结构、各作业的分数占比和截止日期
2. **Canvas Modules / Ed Lessons**：获取课程文件（课件、作业要求、辅助材料等），不同课程老师存放位置不同
3. **Ed Discussion**：海量教师和同学关于作业的有价值讨论（要求澄清、常见错误、评分标准等）
4. **社区 Cheatsheet 仓库（usyd-cs-cheatsheets）**：社区学生贡献的考试速查表，经审核后整合到平台，为复习模块提供高质量的考前参考材料

基于这些第一手信息，平台能够：

- 精确知道哪些作业分数占比高（应该重点投入精力）
- 精确知道哪些作业时间紧凑（需要提前规划）
- 汇总 Ed 上关于每个作业的所有有用信息（要求、澄清、评分标准、常见坑点）
- **通过 AI 辅导任何学科的任何作业，帮助学生拿到高分**

此外，作业辅导系统上线后，可以基于对各作业完成时长的分析，实现更精准的 **风险预警**——不仅告诉学生"你当前分数偏低"，还能告诉学生"这个作业预计需要 X 小时，你需要在 Y 天前开始"。

### 3.2 竞品差距分析 — UniBoard 的差异化机会

**市场中没有任何产品同时做到以下几点：**

1. **Canvas + Ed 双平台深度集成**: 所有竞品最多只集成 Canvas，没有一个集成了 Ed Discussion 和 Ed Lessons。对于悉尼大学等使用 Ed 生态的学校，Ed 上的信息（考试提示、课件、有价值的学生提问）对 GPA 的影响巨大。
2. **GPA 导向的信息筛选**: 竞品要么是通用 AI 助手，要么是简单的 GPA 计算器。没有产品以 "GPA 最大化" 为唯一设计目标来筛选和推送信息。
3. **文件智能导航**: 没有竞品能对大学课程中杂乱的文件结构进行 AI 智能分类和介绍，帮助学生快速理解每个文件夹的用途。
4. **Ed Discussion 智能挖掘**: 没有竞品能从 Ed Discussion 中智能提取对 GPA 有直接影响的高价值信息。
5. **社区驱动的复习资源**: 没有竞品整合了社区贡献的考试 Cheatsheet 和 AI 复习工具。Atlas 和 Mindgrasp 虽有 AI 学习功能，但缺乏针对特定学校/课程的社区复习资源。

### 3.3 竞品启示

| 竞品经验 | UniBoard 应用 |
|---------|-------------|
| Atlas 的 Canvas 自动同步体验极好 | UniBoard 必须做到一键连接，零配置同步 |

| LearnWise 面向机构定价（非学生个人） | UniBoard 定位 C 端学生，降低使用门槛 |

### 4.2 各模块功能描述

#### 4.2.1 GPA 中枢模块 (P0 — 核心)

平台的核心模块，回答学生最关心的问题："我现在几分？我还需要考多少？下一个 Deadline 是什么？"

- **实时 GPA 追踪**: 自动从 Canvas 拉取成绩并计算 GPA。支持悉尼大学 WAM (Weighted Average Mark) 制度和标准 4.0 GPA 制度。
- **What-if GPA 预测器**: 学生输入假设的未来评估分数，系统实时计算对 GPA 的影响。例如 "如果期末考 80 分，我的 WAM 会变成多少？"
- **目标 GPA 路径**: 设定目标 GPA 后，平台反推每门课剩余评估需要的最低分数，帮助学生分配备考精力。
- **评分权重可视化**: 基于 **Unit Outline**（从 Canvas 侧边栏跳转链接抓取悉尼大学官网的统一格式 HTML 页面）精确获取每门课的评分结构，清晰展示各评估项的权重和已得分情况。数据来源是确定性解析，而非 AI 推断。
- **Deadline 统一视图 (P0)**: 聚合所有课程的截止日期到一个统一时间线视图。数据来源包括三个渠道，去重合并后展示：
  - Canvas Assignments（assignment due_at 字段）
  - Ed Lessons 作业模块（如果 Lesson 中包含作业信息）
  - Ed Discussion 教师评论（教师在帖子中提到的截止日期或截止日期变更）
  - 原因：悉尼大学每门课的老师对作业发布的偏好不同，有的只在 Canvas 发，有的只在 Ed 发，因此必须多来源聚合。
- **风险预警（分阶段实现）**:
  - **Phase 2-3（MVP）**: 简单阈值预警 — 当某门课的成绩轨迹偏离目标 GPA 超过阈值时提醒
  - **Phase 4+（作业辅导系统上线后）**: 智能预警 — 基于对各作业完成时长的历史分析，提前告知学生"这个作业预计需要 X 小时，建议在 Y 天前开始"

#### 4.2.2 文件智能导航模块 (P0)

解决新生和初选课程学生面对大量文件不知所措的痛点。每门课的老师上传习惯不同——有的课件在 Canvas Modules，有的在 Ed Lessons；文件命名风格各异，新生无法快速分辨哪些是 Lecture 课件、哪些是作业要求、哪些是辅助参考材料。

- **文件夹 AI 分类介绍 (P0)**: AI 读取每个文件夹内的文件内容，生成清晰的一句话介绍（如"本文件夹包含每周 Lecture 幻灯片"、"本文件夹包含各次 Assignment 的要求 PDF 和评分标准"）。后台同步课程数据时预生成基础介绍，用户也可手动触发刷新以获取更详细的分析。不同课程的文件可能在 Canvas Modules 或 Ed Lessons 中，系统自动检测并统一展示。
- **文件搜索 (P1)**: 全文搜索课程内所有文件的内容，快速定位知识点或特定文件。
- **单文件 AI 描述 (P2 — 远期)**: 为每个文件生成简短描述（如"Week 3 排序算法 Lecture 幻灯片"），无需逐个打开文件即可了解内容。

#### 4.2.3 信息情报模块 (P0)

解决 Ed Discussion 信息过载的痛点，只推送对 GPA 有直接影响的高价值信息。

**高价值信息的定义：**

| 信息类型 | 对 GPA 的影响 | 示例 |
|---------|-------------|------|
| 考试范围和重点 | 直接影响备考策略 | "Hashing 不在考试范围内" |
| 作业要求澄清 | 直接影响作业分数 | "Task 3 需要写伪代码" |
| 评分标准 (Rubric) | 直接影响得分策略 | "代码注释占 10% 的分" |
| 截止日期变更 | 影响是否能按时提交 | "Assignment 3 延期到下周五" |
| 教师对常见错误的提示 | 帮助避错 | "很多同学忘了处理边界条件" |
| Endorsed 帖子 | 教师认可的正确理解 | 被打 ✅ 的学生回答 |

**过滤的内容：** 纯社交/闲聊、与当前评估无关的讨论、重复信息、非学术技术问题（"WiFi 不好"、"教室在哪"）。

#### 4.2.4 AI 学习助手 → 作业辅导系统 (P1 → Phase 4+)

**MVP 阶段 (P1-P2):**

- **基于课件的 AI 问答**: 同步的课件作为 AI 知识库，学生可以针对性提问。AI 回答必须引用具体课件来源，不编造内容。
- **单元复习 (P2)**: 学生选择某门课的某个单元后，获得两类复习支持：
  - **AI 复习摘要**: AI 基于该单元的课件内容和 Ed Discussion 中的高价值信息（考试范围提示、易错点、教师澄清等），生成结构化的复习文档（知识重点、易错点、考试范围预测）。
  - **社区 Cheatsheet**: 如果该课程在社区 cheatsheet 仓库（usyd-cs-cheatsheets）中有考试速查表，在平台内嵌展示并支持下载。Cheatsheet 由 USYD 学生社区贡献，经仓库维护者审核后合并。

**远景阶段 (Phase 4+) — 全学科作业辅导平台:**

平台利用第一手数据链（Unit Outline + Canvas/Ed 课件 + Ed Discussion）构建完整的作业辅导能力：

- **交互式 AI 复习问答（Phase 4+）**: 学生选择要复习的单元后，AI 基于课件 + cheatsheet + Ed Discussion 内容进行交互式复习——向学生提问、评价学生的回答、讲解薄弱知识点，类似 AI 私人家教。追踪学生在各知识点上的掌握程度，重点强化薄弱环节。
- **AI 作业辅导**: 学生在做作业时，AI 结合作业大纲、评分标准（来自 Unit Outline）、课件内容、Ed 上教师/同学的有用讨论，给出针对性辅导建议，帮助学生拿高分。
- **作业"性价比"分析**: 基于 Unit Outline 中各作业的分数占比和截止日期，帮助学生识别高权重/低难度的作业（应重点投入），以及时间紧凑需提前规划的作业。

#### 4.2.5 用户引导 (P0)

- **3 步完成连接**: ① 注册账号 → ② 按图文引导在 Canvas/Ed 获取 API Token → ③ 粘贴 Token 完成连接
- **零安装**: Web 端为主要入口，无需安装浏览器插件或桌面应用
- **MCP 入口**: 面向技术用户，支持通过 Claude Desktop 直接使用 MCP 工具

#### 4.2.6 个性化 Dashboard (Phase 4+ — 远景)

上线后迭代功能，不属于 MVP。

- **注册引导问卷**: 新用户注册时回答一系列问题（专业、年级、GPA 目标、学习偏好、关注重点等）
- **定制化 Dashboard**: 根据问卷答案定制 Dashboard 布局、模块优先级、信息推送频率
- **动态调整**: 随着使用数据积累，自动调优推荐和展示策略

### 4.3 功能边界 — 明确不做

| 不做的功能 | 原因 |
|-----------|------|
| Ed Discussion 发帖/回复/评论 | 会产生垃圾信息，污染 Ed 生态 |
| Canvas 作业提交 | 存在学术诚信风险 |
| Canvas 考试/Quiz 作答 | 存在学术诚信风险 |
| 作业代写或直接给答案 | 违反学术诚信 |
| 社交/聊天/非学术功能 | 与 GPA 无关 |
| 课程推荐/选课建议 | 超出 GPA 追踪范围，v1 不做 |

> **核心原则：UniBoard 对外部平台只读不写（Read-Only），所有写操作仅限于 UniBoard 内部数据（如用户设置、缓存、笔记）。**

### 4.4 边界场景处理

| 场景 | 处理策略 |
|------|---------|
| 某门课没有 Ed Discussion | 正常运作，信息情报模块仅聚合 Canvas 数据，UI 中标记"此课程无 Ed 数据" |
| 某门课没有 Unit Outline Tab | 从 Canvas assignment_groups 获取近似权重作为 fallback，UI 中标记"权重数据来自 Canvas（可能不完整）" |
| Unit Outline HTML 格式异常/解析失败 | 返回原始 HTML 供人工查看；记录日志以便开发者修复解析器；GPA 计算 fallback 到 Canvas 数据 |
| 教师未在 Canvas 上传成绩 | 该评估项显示为"未出分"，GPA 计算基于已出分项目；不假设得 0 分 |
| Canvas/Ed API Token 失效 | 在 1 小时内检测并通知用户重新授权；失效期间显示最后缓存数据并标记"数据可能不是最新" |
| 教师更改评分结构（学期中） | 下次 Unit Outline 刷新时自动更新；支持用户手动触发刷新 |
| 课程同时使用 Canvas Discussion 和 Ed Discussion | 当前版本仅聚合 Ed Discussion；Canvas Discussion 作为 Phase 5 扩展考虑 |

## 5. 成功指标 (KPIs)

### 5.1 北极星指标

**使用 UniBoard 的学生，学期末 GPA 是否高于使用前 / 高于未使用的对照群体。**

> 注：这是长期指标，短期无法直接衡量。以下 KPI 作为代理指标。

### 5.2 用户获取指标

| 指标 | Phase 1 目标 | Phase 2 目标 | 衡量方式 |
|------|------------|------------|---------|
| 注册用户数 | — (Phase 1 无 Web 端) | 500 | 数据库统计 |
| PyPI 下载量 | ≥ 50 | — | PyPI Statistics |
| GitHub Stars | ≥ 10 | ≥ 50 | GitHub 仓库统计 |
| API Token 连接成功率 | > 80% | > 90% | 注册→连接成功的转化率 |
| 引导流程完成率 | > 70% | > 85% | 开始引导→完成引导 |

### 5.3 用户参与指标

| 指标 | 目标 | 衡量方式 |
|------|------|---------|
| 周活跃用户 (WAU) | > 60% 注册用户 | 每周至少登录一次 |
| 考试周 DAU 增幅 | > 2x 日常 | 考试周 vs 非考试周 DAU |

| 指标 | 目标 | 衡量方式 |

| 用户反馈为 "有用" 的比例 | > 75% | 摘要底部的 👍/👎 反馈 |

| 指标 | 目标 | 衡量方式 |
|------|------|---------|

| Canvas/Ed 数据同步延迟 | < 15 分钟 | 最后同步时间 vs 当前时间 |
| 用户 Token 失效检测 | < 1 小时 | 自动检测并通知用户重新授权 |

## 7. 安全与合规（业务层面）

### 7.1 学术诚信

- 平台定位为 **学习辅助工具**，不是作弊工具
- AI 助手不直接给出作业答案，而是引导学习
- 不访问考试/Quiz 内容
- 只聚合公开可见的课件和讨论信息

### 7.2 隐私

- 仅收集学业相关数据，不收集个人隐私信息
- 用户 API Token 加密存储，不明文展示
- 支持用户数据导出和一键删除
- 不收集、存储或传播其他学生的个人信息

### 7.3 平台合规

- 遵守 Canvas API 使用条款
- 遵守 Ed API 使用条款
- 对外部平台只读访问，不执行任何写操作
- 明确的隐私政策和使用条款

## 8. 产品路线图

### Phase 1: MCP 功能补全 + 开源基础 (2-3 周)

**里程碑**: MCP 工具覆盖 Canvas Modules + Ed Lessons + Unit Outline，开源项目可被其他开发者使用

- 补全 Canvas Modules 和成绩获取功能
- 新增 Ed Lessons 课件获取功能
- **新增 Unit Outline 抓取功能**（Canvas 侧边栏 → 悉大官网 HTML 解析 → 评分结构 + 作业描述 + 截止日期）
- 移除所有对外部平台的写操作
- 代码质量提升（类型注解、测试、文档）
- 更新 GitHub README 和发布 PyPI 包

**KPI 检查点**: MCP 工具功能测试通过率 100%，GitHub Stars ≥ 10，PyPI 下载量 ≥ 50

### Phase 2: Web MVP + GPA 核心 (3-4 周)

**里程碑**: Web 端可用，核心 GPA 追踪、Deadline 聚合和文件智能导航功能上线

- 用户注册和 Token 配置引导
- GPA 实时追踪仪表盘 + What-if 预测器
- **评分权重可视化（基于 Unit Outline 数据）**
- **Deadline 统一视图（Canvas + Ed Lessons + Ed Discussion 三源聚合去重）**
- 文件智能导航（文件夹 AI 分类介绍，覆盖 Canvas Modules 和 Ed Lessons）
- 基础 Ed Discussion 高价值信息展示（规则驱动：Endorsed/Staff 帖子 + Canvas 公告聚合，US-302a）
- 基础每日学业摘要（规则驱动聚合新截止日期/公告/成绩/高价值帖子，US-301a）
- 简单阈值风险预警
- 部署上线

**KPI 检查点**: 50 名种子用户注册（悉尼大学 CS 学生），Token 连接成功率 > 80%，每日摘要打开率 > 40%

### Phase 3: AI 增强 + 推送 (2-3 周)

**里程碑**: AI 驱动的信息筛选和主动推送上线

- AI 驱动的 Ed Discussion 高价值信息筛选（升级 US-302a → US-302b，AI 替代规则驱动）
- AI 增强的每日/每周学业摘要邮件推送（升级 US-301a → US-301b，AI 智能组织和筛选）
- 单元复习功能（AI 复习摘要生成 + 社区 Cheatsheet 内嵌展示）
- 基于课件的 AI 问答
- 缓存和去重机制
- 目标 GPA 路径规划

**KPI 检查点**: 每日摘要打开率 > 60%，AI 筛选准确率 > 85%

### Phase 4: 作业辅导系统 + 个性化 (持续)

**里程碑**: 从信息聚合平台进化为全学科作业辅导平台

- **AI 作业辅导系统**: 基于 Unit Outline + 课件 + Ed 讨论，为学生提供作业级别的 AI 辅导
- **作业"性价比"分析**: 基于评分权重推荐精力分配策略
- **智能风险预警**: 基于作业完成时长分析的提前预警
- **个性化 Dashboard**: 注册引导问卷 + 定制化模块布局
- **交互式 AI 复习问答**: 基于课件 + cheatsheet 的 AI 家教模式复习
- 探索 Studocu 等平台的数据合作

**KPI 检查点**: 作业辅导使用率 > 30% 活跃用户，用户满意度 > 80%

### Phase 5: 扩展与生态 (持续)

**里程碑**: 支持更多大学，形成开源社区

- 抽象化 Platform Adapter 支持 Moodle、Blackboard
- 移动端 PWA
- 社区贡献机制
- 探索商业模式

**KPI 检查点**: 500+ 注册用户，≥ 2 所大学适配
